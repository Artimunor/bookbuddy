# Client privacy review — 2026-11-24 (independent reviewer)

HEAD reference: `07a3bb800400fec88111a723206308a031aa499f`. Static, read-only review. `M/` = `apps/mobile/src/`; `W/` = `apps/web/src/`.

**High**
1. **The portal has no sign-out control.** `W/portal/now/common.tsx:77-87`, `W/portal/settings/index.tsx:7-24`. Closing the tab leaves a persistent session cookie; the next person using that browser can reopen the customer’s jobs. The server issues a 30-day session and already supports revocation (`apps/api/src/modules/auth/otp.ts:21`, `routes.ts:142-147`). Expose sign-out, confirm server revocation, and clear private state across tabs.
2. **An old tab can submit one customer’s data under another customer’s cookie.** `W/portal/session/index.tsx:44-63`, `W/portal/session/pending-operation.ts:39-45,69-71`, `W/portal/places/index.tsx:65-69,113-117`. If another tab signs in as B, A’s open tab still passes its local identity check. Retrying A’s place creation uses B’s cookie; the server assigns ownership to the authenticated account (`apps/api/src/modules/places/commands.ts:87-98`). Bind mutations to the expected session/context on the server and invalidate stale tabs on identity change.
3. **The browser can record and upload audio after the customer leaves the form.** `W/portal/media/MediaPicker.tsx:14,28-36`. If navigation occurs while microphone permission is pending, cleanup sees no stream. A later permission grant starts the recorder on the unmounted form; its timer then uploads the recording. Invalidate pending capture on unmount, stop late-arriving tracks, and suppress uploads from cancelled captures.
4. **Arrival notes accept a bare entry PIN.** `packages/domain/src/access-code.ts:11-19`, `M/screens/c-03/Screen.tsx:45`, `M/screens/c-02/draft.ts:64-71`, `apps/api/src/modules/places/routes.ts:69-84`. A customer entering just the keypad number passes the detector; mobile autosaves it and the place API uses the same detector. Use structured non-secret handoff choices for arrival instructions; at minimum, reject PIN-only notes before either local or server persistence.

**Medium**
5. **Private command bodies survive portal reloads.** `W/portal/places/index.tsx:113-122`, `W/portal/session/pending-operation.ts:59-66`, `W/portal/session/pending-storage.ts:30-42`. Saving a place writes its address and arrival note to `sessionStorage` before sending. An uncertain response leaves the body there; a session-prefixed key does not protect it from other same-origin code. Persist only an operation ID and route; recover the outcome through an authenticated receipt lookup.
6. **Native persistence does not distinguish private from shared phones.** `M/session/provider.tsx:84-94,103-118`, `M/screens/c-01/Screen.tsx:22`, `M/repository/open.native.ts:17-36`. The app restores the last session and opens its persistent job cache without a device-eligibility gate. A second person handed the same unlocked phone can reopen the cached customer view offline. Default to memory-only unless the device is approved for individual offline use.
7. **Offline sign-out can leave push delivery active.** `M/session/provider.tsx:49-56,164-175`, `M/system/push/index.ts:86-97`, `apps/api/src/effects/push.ts:43-51,78-86`. Local sign-out completes without checking whether session-end reached the server. The server can continue sending the former account’s alerts to that phone, even though its settings show notifications off. Lock locally immediately, but retain a narrowly scoped revocation intent until acknowledged.
8. **A revoked worker assignment can leave its status card visible.** `M/repository/repository.ts:579-594`, `M/system/status-cards/index.tsx:125-133`, `M/system/status-cards/controller.ts:89-93`. Sync can remove the shift while the session stays active. With no departure event and no shift projection, the host neither refreshes nor stops the card; an opted-in detailed card can still show check-in or hold information. End the native card on definitive removal or denial, distinct from initial loading.
9. **Sign-out deletes unresolved work that the confirmation does not fully count.** `M/repository/repository.ts:118-135,329-340`, `M/screens/s-06/Screen.tsx:47-50,63-72`. The dialog warns about a wipe, but its checking count reads only the outbox. A pending online approval receipt can be omitted and then deleted along with unsent attendance and staged evidence. Separate visible-cache purge from account-sealed unresolved work; count receipts and require disposition before destroying the only local record.
10. **Draft expiry can destroy an uncertain submission.** `M/screens/c-04/Screen.tsx:30-42`, `M/repository/repository.ts:371-373`. A lost request response leaves its operation marker in the draft, but the 14-day cleanup deletes it as if it were unsubmitted. The review screen then lacks the payload it requires to check the send. Move submitted requests into a distinct reconciliation state before transmission; expire only unsubmitted drafts.
11. **Old pending work can send automatically without the required disposition.** `M/repository/repository.ts:524-551`, `M/media/queue.ts:83-99`, `M/media/provider.tsx:46-59`. Reconnect selects queued attendance and selected uploads without an age gate. Work left unresolved for 30 days can therefore send without human review. Surface it at day seven and hold it for disposition at day 30.
12. **Removing a request photo does not always stop its upload.** `M/screens/c-02/request-media.ts:23-27`, `M/repository/repository.ts:694-696,718-725`, `M/media/queue.ts:169-181,231`. A transfer is marked started *before* requesting a grant. Removing it after a network interruption can hide it from the draft while leaving it selected for upload on reconnect. Persist cancellation in the queue; never issue a new PUT for a removed item, and reconcile any PUT already in flight.
13. **The 100 MiB device staging cap is not enforced.** `M/media/files.native.ts:6-15`, `M/repository/repository.ts:669-680`, `packages/api-contract/src/media.ts:5-11`. Per-file and per-draft checks permit multiple offline drafts to consume the device’s remaining storage, jeopardizing later attendance writes. Atomically reserve bytes across the account’s contexts before copying and release the reservation on cleanup.
14. **A crash can leave private media behind after sign-out.** `M/media/attach.ts:81-89`, `M/media/files.native.ts:10-15`, `M/repository/repository.ts:118-125`. A photo or recording is copied before its queue row exists. If the process dies between those steps, sign-out cannot find the file because it enumerates database rows only. Journal ownership before copying and reconcile interrupted copies on startup.
15. **Abandoned, unselected media outlives its draft.** `M/repository/repository.ts:371-373,675-682,692-696`. A captured file starts unselected. Draft expiry removes only the draft row, and the transfer worker skips unselected files. An abandoned private capture can consequently remain until account wipe. Expire draft-owned, never-submitted files with the draft without deleting uncertain transfers.

**Low**
16. **Place searches enter browser history.** `W/portal/places/index.tsx:19-28`. Search text is copied into both the URL and the detail page’s `history.state`; an address or identifying alias remains after leaving the portal. Keep the filter and return state in memory.
17. **The shipped portal has no explicit framing policy or CSP.** `apps/web/index.html:3-10`, `apps/web/vite.config.ts:28-35`, `apps/web/README.md:7-13`. Following the checked-in static-host instructions alone does not prevent another same-site origin from framing a customer confirmation screen. Ship response headers including `frame-ancestors 'none'` and a CSP restricted to the app’s actual script, connection, and media origins. Production edge overrides were not verified.
18. **Photo encoders exceed the specified default resolution.** `M/media/attach.ts:43-50`, `W/portal/media/upload.ts:9-18`, `docs/architecture/fable-implementation-plan.md:197`. Mobile retains up to 3,072 pixels on the long edge and web 2,400, versus the specified 2,048. Apply the same 2,048-pixel default before JPEG encoding on both clients.

**Checked and OK — static evidence**
- SQLCipher availability is checked before use; the database key and bearer use device-only SecureStore. Android disables backup, and iOS requires the exclusion marker before opening the offline store.
- Projection and GET-cache writers select explicit fields, partition by account/context, and enforce snapshot expiry. Reviewed allowlists exclude residential addresses, payment instructions, notification link tokens, and received media.
- Both photo paths encode decoded pixels rather than forwarding the source file. Signed transfer URLs stay out of persisted queue rows; native staged-file deletion checks the private directory boundary.
- Push taps require the configured HTTPS host and an opaque `/l/` path. Link resolution checks the signed-in scope. Hidden status-card details are excluded from the generic accessibility text on both platforms.
- Portal user text is rendered as React text, including `dir="auto"` passages; no application raw-HTML sink or explicit client logging of bearers, OTPs, or signed media URLs was found. Checked-opening history handoffs use a nonce rather than the private projection.

Signed-device backup/restore, generated release permissions and ATS settings, OS media caches, VoiceOver/TalkBack output, deployed association files, and production headers remain unverified.
