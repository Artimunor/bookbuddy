# Auth and session review — 2026-11-24 (independent reviewer)

**Review baseline:** `07a3bb800400fec88111a723206308a031aa499f`. `main` advanced during the review, including a change to realtime code. The findings below are supported by source reads, but this is **not an immutable-HEAD sign-off**.

### High

1. **A stale portal tab can write one customer’s data into another customer’s account.** `apps/web/src/portal/session/index.tsx:43–63`, `apps/web/src/portal/places/index.tsx:65–68,115–117`, `apps/api/src/modules/places/commands.ts:87–95`. If a second tab signs in as B, the first can still display A while its next create-place request uses B’s cookie. The server assigns A’s submitted address to B. Bind writes and retries to the expected session/context and reject mismatches; notify other tabs when identity changes.
2. **Portal users have no sign-out control.** `apps/web/src/portal/settings/index.tsx:7–24`, `apps/web/src/portal/session/index.tsx:20–30`, `packages/api-client/src/auth.ts:20`. The client implements session end, but the portal never calls it. Closing a shared browser tab leaves the persistent cookie usable by the next person. Expose sign-out, revoke server-side, and clear pending operations and handoffs across tabs.
3. **Mobile sign-out can report success without revoking the bearer or push registration.** `apps/mobile/src/session/provider.tsx:49–56,164–177`, `apps/api/src/modules/auth/commands.ts:63–77`. The app discards the session-end result and deletes its credential. After an offline or failed request, a copied bearer remains valid and the server can still send pushes to that installation. Lock locally immediately, but retain a protected, revocation-only retry until the server confirms.
4. **A place delegate can grant access they no longer hold.** `apps/api/src/modules/places/commands.ts:230–236,270–276,337`, `apps/api/src/modules/access/policy.ts:33–39,49–56`. Removing a delegate’s view grant leaves `delegate` live; neither invitation issue nor acceptance requires the inviter still to hold `view`. Another recipient can consequently obtain the address. Require the inviter to hold the capability being delegated at both issue and acceptance.
5. **Changing an address can carry approval authority to the new property.** `apps/api/src/modules/places/commands.ts:121–130,155–174,182–188`, `apps/api/src/modules/commercial/policy.ts:83–89`. An address reset revokes booking/request grants but preserves the named approver and approval grant. Fresh verification of the **owner alone** restores commercial authority to the old approver; old approver proofs can also be reused. Bind protected grants and proofs to the verified address revision.
6. **Revoking and re-inviting a viewer exposes jobs from the period without access.** `apps/api/src/modules/places/commands.ts:270–276,344–348`, `apps/api/src/modules/access/commands.ts:169–178`, `apps/api/src/modules/places/read.ts:23–24`. View removal leaves the person row open. A new invitation restores view without advancing `history_from`, so intervening bookings appear. Start a new history boundary when view is reacquired after a lapse.
7. **Removing a foreman role can leave backup-job authority ready to reactivate.** `apps/api/src/modules/access/commands.ts:151–156,335–343`, `apps/api/src/modules/schedule/policy.ts:30–36`. The single-role revoke path leaves `backup_foreman` live when the person retains a worker role. Restoring ordinary foreman membership reuses the context ID, making still-live backup job grants effective again without a fresh backup appointment. Use the same dependent-grant cleanup for both role-edit paths.
8. **Mobile sign-out destroys unresolved authored work.** `apps/mobile/src/session/provider.tsx:49–56`, `apps/mobile/src/repository/repository.ts:118–135`. The account wipe deletes unsent attendance, staged files and uncertain-operation receipts, even when they are the only record. The confirmation warns about deletion but does not reconcile the work. Separate disposable cache from a locked, account-only outbox retained until acknowledgement or explicit disposition.

### Medium

9. **Private portal payloads survive reload in `sessionStorage`.** `apps/web/src/portal/session/pending-operation.ts:59–66`, `pending-storage.ts:39–42` in the same directory, `apps/web/src/portal/new/index.tsx:60`, `apps/web/src/portal/places/index.tsx:115–117`. An uncertain submission leaves the full description, contact, address or arrival note in browser storage. Persist only an opaque operation ID and route; check the server receipt after reload.
10. **The offline bootstrap retains more than the active scope.** `apps/mobile/src/session/provider.tsx:112–120,158`, `apps/mobile/src/repository/repository.ts:104–115`, `apps/mobile/src/screens/s-06/Screen.tsx:78`. The entire bootstrap, including email and all business contexts, is saved and restored against session expiry rather than the 72-hour authorization window. Persist an explicit offline projection; expire it separately from the bearer.
11. **A place can be archived with a live job or unresolved case.** `apps/api/src/modules/places/commands.ts:287–298`, `apps/api/src/modules/places/policy.ts:35–36`. Only an open job with a **booked visit** blocks archive. An open unbooked job or unresolved aftercare case does not, although archive revokes non-view grants. Check both commitments in the archive transaction, as required by `docs/reports/2026-11-23-open-question-suggestions/product-and-platform.md:39`.
12. **Arrival notes can store plainly labelled nonnumeric credentials.** `packages/domain/src/access-code.ts:9–19`, `apps/api/src/modules/places/routes.ts:78–85`, `apps/api/src/modules/places/commands.ts:90–94`. The detector recognizes credential labels but requires numeric patterns; an alphanumeric entry password can be saved verbatim. Reject explicit credential declarations regardless of value format and prefer structured, non-secret handoff instructions.
13. **Signed-in support intake is unthrottled.** `apps/api/src/modules/jobs/commands.ts:414–423,437–445`. The anonymous path enforces three cases per source per hour; the account path checks only operation-ID uniqueness. One verified account can create unbounded cases and outbox work. Apply a rolling account quota while preserving free idempotent replays.
14. **Public OTP routes buffer unbounded JSON before throttling.** `apps/api/src/modules/auth/routes.ts:32–35,68–76,100–109`. Oversized requests consume Worker memory before schema validation or mailbox/device/source limits run. Use a small streaming body limit on all auth JSON routes.
15. **Provider invitation delivery limits reset after withdrawal.** `apps/api/src/modules/access/commands.ts:70–87,128–132`, `apps/api/src/modules/access/policy.ts:82–89`. A withdrawn invitation no longer blocks a fresh issue, and only superseding invitations count as reissues. The same administrator can repeatedly send mail to the same recipient despite the stated limits. Count deliveries by business and recipient across invitation IDs and states.
16. **Production can enable the fake mail transport.** `apps/api/src/effects/index.ts:125`, `apps/api/src/providers/mail.ts:35–44`. The Bun server is separate, but setting `OTP_MAIL_DEV=true` in Worker bindings silently marks real OTP and invitation mail delivered without sending it. Inject the fake transport from the dev entrypoint only; fail closed on dev-only configuration in production.
17. **Direct roster reads can activate a future-dated staff role early.** `apps/api/src/modules/auth/session.ts:21–31,65–70`, `apps/api/src/modules/access/businesses.ts:60–76`. A provisioned but not-yet-effective provider-admin role passes the shared context predicate and can read member emails. The opaque-link path correctly checks `granted_at` (`apps/api/src/modules/links/index.ts:100–104`). Apply that effective-time check to direct reads, bootstrap and context switching too.

### Low

18. **Sign-out leaves existing sockets receiving activity hints.** `apps/api/src/modules/auth/commands.ts:63–80`, `apps/api/src/realtime/live-topic.ts:39–49,58–65`. Attachments identify a scope, not the session. A signed-out socket can observe update timing until its five-minute lease ends; it does **not** receive subsequent message text. Invalidate affected session subscriptions on revocation.
19. **Invalid upgrade credentials can wake arbitrary topic objects.** `apps/api/src/modules/live/routes.ts:13–21`, `apps/api/src/realtime/live-topic.ts:26–32`. The outer route checks credential-header presence, then routes to the named Durable Object before authenticating. Rejected upgrades can therefore consume object quota. Reject malformed credentials before routing and rate-limit unauthenticated upgrades at ingress.

### Checked and OK

- **OTP:** Random six-digit codes, keyed attempt/mailbox binding, atomic consumption, resend invalidation and independent failure buckets. Start does not consult account existence; cooldown responses can reveal recent mailbox activity, not registration.
- **Session transport:** Host-only `Secure; HttpOnly; SameSite=Lax` cookie; exact-Origin checks for cookie writes and upgrades; native bearer kept in device-only SecureStore. Server-side session end revokes the session and device push rows in one batch.
- **Access and links:** Pending acceptance checks the verified mailbox digest and any pinned recipient ID. Stored links check recipient scope and expiry before projection. Ordinary approver replacement changes the grant and named person atomically.
- **Portal navigation:** No external-origin `next` redirect found. Checked link handoffs are in-memory, one-shot and bound to session and context.
- **Dev server:** Wrangler selects `src/index.ts`; no Worker import of `apps/api/dev/**` was found. The Bun listener binds loopback and validates Host. This excludes the listener, **not** the fake mail branch in finding 16.

**Not covered:** No tests, servers, payloads or network calls were run. Deployed Worker artifacts, edge rules, production bindings and physical-device storage were not inspected. No shell was available for `git rev-parse` or an immutable checkout; the baseline hash was read from Git’s HEAD ref.
