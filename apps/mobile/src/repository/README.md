# Mobile offline data

Sync stores notification IDs, kinds and timestamps, and two assignment-keyed projections for the active worker. `worker_field_shift` keeps booking, work, hold and attendance facts. `assignment_briefing` keeps versioned safety text, its reviewed human reading aid, booking and hold metadata, but no arrival plan. Opted-in GETs store safe `home`, `jobs_list`, `shift_agenda`, `crew_availability` and `notification` pages. The field allowlists in `cache.ts` and `remote-cache.ts` exclude residential aliases, addresses, access details, bills, payment instructions, notification link tokens and received media.

For a customer booking, `session_booking` keeps the booking ID, title, category, time, zone, party size and state, confirmed host name and substitute flag, pending proposal deadline, agreed unit price and public venue name and locality. It never keeps addresses, access notes, attendee or other contact data, or payment instructions.

Only the active account and context can read a snapshot. Customer snapshots and their sync cursors stay in memory; staff snapshots can persist on eligible native devices. Each cached GET expires 72 hours after its own confirmation. The separately timed offline bootstrap contains only the display name, active context ID/role/business name, and preferences. It never carries the email address, other contexts, or bearer. A definitive removal or denial ends the affected status card; an incomplete snapshot does not.

Authored drafts use `kind:id` keys. Each request has its own ID, and the first read of a legacy `request:new` draft moves it without changing its contents or age. Drafts warn after 11 idle days and expire after 14. An online-only command saves its route, resource ID and stable operation ID before sending. A lost response keeps that receipt for Checking; it contains no request body and sync never replays it. Unsent outbox entries can be removed, and an explicit retry starts or joins one sync run for the active context.

Attendance captures use a stable operation ID. Acknowledged captures leave the outbox even if the assignment projection is on a later page. Only the matching attendance event or its review ID can mark a capture recorded or needing review. A lost response leaves it Checking with the original ID.

Sign-out locks the UI and replaces the bearer with a device-only SecureStore revocation marker. The next eligible connection retries revocation until the server acknowledges it, including revocation of the device’s push registration. The sign-out sheet counts queued operations, uncertain receipts, drafts and staged evidence. Keeping work purges the cached views and seals the authored work to that account; discarding also removes its authored rows and files.

Progress links wait until every referenced local photo is ready for the same assignment. Transfer failures stay unsent and can be retried or removed. A sync response stores the exact per-photo outcomes and timestamp with the cursor, independent of whether the screen is open. The receipt contains IDs, outcome codes and times, not captions or files.

Native uses a device-only SecureStore key and SQLCipher. A cold open of existing durable data requires device passcode or biometric authentication; a device without enrolled authentication uses memory-only storage. The iOS config plugin excludes `BookBuddyOffline` from backups before the repository opens; this requires a native build, not Expo Go. Evidence is staged under the private durable or temporary directory according to the same policy. The React Native Web gallery uses a preview-only in-memory executor.
